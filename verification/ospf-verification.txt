OSPFv2 Verification
Devices: R1, DSW1, and DSW2
================================================================

PURPOSE
-------

This verification demonstrates OSPFv2 operation between the
enterprise edge router R1 and the two Layer 3 distribution switches,
DSW1 and DSW2.

The lab uses OSPF process 1 and Area 0.

OSPF provides dynamic IPv4 route exchange between R1 and the
distribution layer.

The user VLAN interfaces on DSW1 and DSW2 are configured as passive
interfaces. This allows their connected IPv4 networks to be
advertised into OSPF without attempting to form OSPF neighbor
relationships with end hosts.

================================================================
OSPF DR / BDR OBSERVATION
================================================================

The R1-to-distribution links are Ethernet interfaces.

OSPF therefore uses the broadcast network type by default.

Even though each transit segment contains only two OSPF routers,
OSPF still performs DR/BDR election on the Ethernet segment.

This explains the observed states:

R1:
  DSW1 -> FULL/DR
  DSW2 -> FULL/DR

DSW1:
  R1 -> FULL/BDR

DSW2:
  R1 -> FULL/BDR

The FULL state confirms that the OSPF databases have synchronized
successfully between the neighbors.


================================================================
PASSIVE INTERFACE DESIGN
================================================================

The distribution-switch OSPF configuration includes passive
interfaces for the enterprise VLAN SVIs.

These interfaces advertise their connected networks into OSPF while
preventing OSPF Hello packets and neighbor formation on user-facing
VLANs.

The distribution transit SVI, VLAN 40, is also configured as passive.

As a result:

  DSW1 and DSW2 do not form an OSPF neighbor relationship directly
  with each other across VLAN 40.

However:

  10.0.1.136/30 remains advertised as an OSPF-connected network.

R1 therefore learns the 10.0.1.136/30 network from both distribution
switches.


================================================================
REDUNDANT ROUTING OBSERVATION
================================================================

R1 installs equal-cost OSPF routes through both DSW1 and DSW2 for:

  10.0.1.0/27
  10.0.1.32/27
  10.0.1.64/27
  10.0.1.96/27
  10.0.1.136/30

For the departmental VLANs, the routing table contains two next hops:

  via DSW1 - 10.0.1.130
  via DSW2 - 10.0.1.134

Both paths have:

  Administrative Distance: 110
  OSPF Metric:             2

This verifies equal-cost route installation across the redundant
distribution layer.


================================================================
VERIFICATION RESULTS
================================================================

PASS

The OSPF verification confirms:

  - R1 has a FULL OSPF adjacency with DSW1.
  - R1 has a FULL OSPF adjacency with DSW2.
  - DSW1 has a FULL OSPF adjacency with R1.
  - DSW2 has a FULL OSPF adjacency with R1.
  - Enterprise VLAN networks are dynamically advertised toward R1.
  - Server networks are dynamically advertised toward both
    distribution switches.
  - R1 installs equal-cost routes through DSW1 and DSW2.
  - Passive interfaces prevent unnecessary OSPF neighbor formation
    on user-facing VLANs.
  - The OSPF control plane is operational across the routed
    enterprise infrastructure.


================================================================
CONCLUSION
================================================================

OSPFv2 Area 0 is operating successfully between the enterprise edge
router and the redundant distribution layer.

The routing tables demonstrate dynamic exchange of enterprise,
transit, and server-network routes.

The dual distribution design provides R1 with two equal-cost OSPF
paths toward the enterprise VLAN networks while each distribution
switch dynamically learns the remote infrastructure and server
networks through R1.
